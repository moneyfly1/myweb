## 零、先明确两件事

1. **只有两个脚本需要关心**：`install.sh`（唯一实现）与 `bt-deploy.sh`（宝塔入口，64 行薄封装，转交 install.sh，行为完全一致）。
2. **宝塔环境下为什么要在面板里建站**：站点记录、vhost、日志目录由面板维护；脚本采用「合并模式」——保留面板的 `#SSL-START`/`#CERT-APPLY-CHECK` 标记与 include，只注入本应用必需的片段（`/api/` 反代、`/uploads/` 反代、SPA 回退、`index.html` 不缓存、`client_max_body_size`、ACME 放行段），并把 `root` 指向前端产物 `frontend/dist`。

## 一、前置条件

| 项 | 要求 |
|----|------|
| 系统 | Debian 10+ / Ubuntu 18.04+ / CentOS 7+ / Rocky / AlmaLinux（实测 Debian 12） |
| 机器 | ≥1 核 / ≥1 GB 内存（**建议 2 GB**：宝塔 nginx 需源码编译）、≥10 GB 磁盘 |
| 域名 | A 记录已解析到本机 IP |
| 端口 | 放行 22（SSH）、80、443，以及**宝塔面板端口**（安装后可知，可在面板设置里改） |
| 网络 | 能访问 GitHub、go.dev、nodejs.org、Let's Encrypt（首次安装需下载 Go/Node） |

## 二、步骤 1：安装宝塔面板

还没有面板的话：

```bash
wget -O /root/bt_install.sh https://download.bt.cn/install/install_lts.sh
yes | bash /root/bt_install.sh          # ⚠️ 必须喂 yes
cat /tmp/btpanel-install.log            # 打印面板地址 / 用户名 / 密码，记下来
```

> ⚠️ **为什么必须 `yes |`**：宝塔官方安装脚本在 stdin 关闭（EOF）时会进入
> `while … read -p …` 的忙循环 —— 实测 **99% CPU 空转 9 分钟且毫无进展**。
> 这是宝塔脚本自身的问题（不是本项目的），加 `yes |` 即可自动应答所有交互提示。

面板地址形如 `https://<IP>:<端口>/<安全入口>`，用户名/密码在安装日志里。

## 三、步骤 2：在面板里安装 Nginx

面板 → **软件商店** → 搜索 **Nginx** → 安装（1.28 即可）。或走命令行：

```bash
bash /www/server/panel/install/install_soft.sh 0 install nginx 1.28
```

> ⏱️ **实测耗时 25–40 分钟**（2 核机器）：宝塔会**从源码编译 OpenSSL + nginx（带 LuaJIT）**。
> 这不是卡住 —— 想看进度用 `ps -ef | grep make`，或 `tail -f /tmp/nginx_make.pl`。

装好后宝塔 nginx 由 `/etc/init.d/nginx` 管理（注意：系统自带的 `systemctl` nginx 单元在宝塔机上通常是
`inactive/failed`，脚本已做识别，不会误判"nginx 未运行"，也不会去启动另一个 nginx 抢 80 端口）。

## 四、步骤 3：在面板里创建站点

面板 → **网站 → 添加站点**：

| 字段 | 填法 |
|------|------|
| 域名 | `你的域名` |
| 根目录 | 保持默认 `/www/wwwroot/你的域名` ← **目录名必须等于域名**（脚本用目录名当域名） |
| PHP 版本 | **纯静态** |
| 数据库 / FTP | 都不创建 |

> 脚本**不会**替你在面板注册站点；要在面板里看到并管理这个站点，就必须用面板建站。

## 五、步骤 4：只下载两个脚本（代码让脚本自己拉）

```bash
cd /www/wwwroot/你的域名
rm -f index.html 404.html .user.ini          # 清掉面板占位文件（更干净）
curl -fsSLO https://raw.githubusercontent.com/moneyfly1/myweb/main/install.sh
curl -fsSLO https://raw.githubusercontent.com/moneyfly1/myweb/main/bt-deploy.sh
```

**不需要手动 `git clone`**：脚本里的 `ensure_source_code` 会自动把仓库拉进这个目录，
并且**支持非空目录**（面板的占位文件存在时也能成功，已实测）。需要能访问 GitHub。

> 也可以手动克隆（目录已空时）：`git clone https://github.com/moneyfly1/myweb.git .`

## 六、步骤 5：一键部署

```bash
bash bt-deploy.sh
# 菜单输入 1（一键全自动部署）；Redis 那步没有 Redis 就答 n
```

非交互（脚本对 EOF 安全，不会空转）：

```bash
printf '1\nn\n' | bash bt-deploy.sh
```

脚本依次会做：

1. **探测环境**：识别宝塔 nginx（`/www/server/nginx/sbin/nginx`）、站点目录 `/www/server/panel/vhost/nginx`、宝塔 pid 文件；
2. **自举依赖**：基础包（git/sqlite3/wget/curl）→ gcc → **Go 1.25.0** → **Node 22.12.0**（nginx 直接用宝塔的，不重复装）；
3. **取源码**：目录为空时自动 clone；
4. **生成 `.env`**：`HOST=127.0.0.1`、数据库**绝对路径**、随机 `SECRET_KEY`、权限 600，并**自动生成管理员账号密码**写入 `ADMIN_USERNAME/ADMIN_EMAIL/ADMIN_PASSWORD`；
5. **构建**：后端 `CGO_ENABLED=1` 编译到 `server.new` → 校验 → 替换（旧版留 `server.bak.<时间戳>`）；前端按 lockfile 装依赖并构建；构建后自动修正前端产物权限（宝塔 nginx 以 `www` 运行，权限不对会 403）；
6. **服务**：写 systemd 单元（含 `EnvironmentFile`/`LimitNOFILE`/`NoNewPrivileges`）→ 启动 → `/health` 业务健康检查；
7. **站点配置（合并模式）**：注入必需片段 + 把 `root` 指到 `frontend/dist`，面板标记与 include 原样保留；写完先 `nginx -t`，失败自动换 http2 写法或**精确回滚本次修改**；
8. **证书**：见下一步；
9. **收尾**：logrotate 配置、升级前数据库备份目录 `/www/backup/cboard`，最后**打印登录地址与管理员账号密码**（并当场实测登录一次）。

## 七、步骤 6：证书二选一（重要，别混用）

### 方案 A：交给宝塔面板管（宝塔用户推荐）

```bash
CERT_MANAGER=panel bash bt-deploy.sh     # 把 SSL 正式交还面板（清掉脚本写的证书段）
```

然后 **面板 → 网站 → 你的域名 → SSL → Let's Encrypt → 申请**。
面板会把证书写到 `/www/server/panel/vhost/cert/<域名>/`、把 `listen 443 ssl` 与证书指令写进它自己的
server 块（`#SSL-START/#SSL-END`），并自己切 HTTPS；**之后续签由面板自动完成**。
脚本只负责检测复用，日志会明确写"已跳过 certbot 申请、不接管续期"。

> 为什么必须先把 SSL 交还面板：宝塔部署证书前会检查配置里是否已存在 `ssl_certificate`，
> **只要存在就认为"已开启 SSL"而跳过写它自己的证书**，于是面板里点申请会"成功"但
> `vhost/cert/<域名>/` 里没有证书、后续"续签"也找不到可续订单 → 表现为续签失败。

### 方案 B：交给脚本（certbot）管（默认）

第 5 步跑完即可。脚本用 certbot 签发并把证书指令按**宝塔格式**写入面板的 server 块
（面板据此显示"已开启 SSL"），自动续期由 `certbot.timer` + 续期钩子完成。

⚠️ 此时**不要在面板点"申请/续签"**：宝塔没有这张证书的订单，点了不会得到正确结果。
需要续期就执行 **菜单 10**（或等 `certbot.timer` 自动跑）。

> 两套证书并存时脚本会**告警**，并指出站点当前实际使用的是哪一套。

## 八、步骤 7：记下登录信息

部署结束（菜单 2 建号后、菜单 8 重启后同样会打印）：

```text
================== 登录信息 ==================
  前台地址:     https://你的域名
  前台登录:     https://你的域名/login
  管理后台:     https://你的域名/admin
  管理员登录:   https://你的域名/admin/login
----------------------------------------------
  管理员账号:   admin
  管理员邮箱:   admin@你的域名
  管理员密码:   <16 位强随机>
  （密码由 .env 的 ADMIN_PASSWORD 固定：应用每次启动都会按它重置，重启后依然可用；
    如需修改：改 .env 后菜单 8 重启，或用菜单 2 重置）
==============================================
✅ 已实测：用上面这个账号密码登录成功
```

**为什么这个密码"永远能显示"**：脚本把生成的密码写进 `.env` 的 `ADMIN_PASSWORD`，
而应用**每次启动都会把该管理员的密码重置成这个值**（账号被锁定也能登录）。
对比：应用自带默认行为是"首次启动生成随机密码、只在 `server.log` 打印一次"，日志被清理/轮转后就找不回来了。

## 九、日常运维（菜单速查）

在站点目录执行 `bash bt-deploy.sh`（或 `bash install.sh`）：

| 项 | 用途 |
|----|------|
| 1 | 一键全自动部署（重复执行安全：幂等，会先备份数据库与旧二进制） |
| 2 | 创建/重置管理员（密码不回显；留空自动生成；建完当场实测登录） |
| 3 | 强制重启服务（**只清理本项目进程，不会误杀宝塔 nginx/redis/mysql**） |
| 4 | 深度清理缓存（清 Redis 本项目键 + 清空 server.log + Go 编译缓存；**保留** `dist` 与二进制） |
| 5 | 解锁用户账户 |
| 6 / 7 | 服务状态 / 实时日志（`tail -f server.log`） |
| 8 / 9 | 重启 / 停止服务 |
| 10 | 证书续期（脚本管证书时用它；面板管证书时用面板） |
| **11** | **从 GitHub 同步并重建**（升级入口；fetch 失败会报错而不假装"已是最新"；先备份库再原子替换） |
| 12 | 配置 Redis 缓存（可选；只监听 127.0.0.1） |
| **13** | **回滚到升级前版本**（`server.bak.*`；数据库备份在 `/www/backup/cboard`） |
| 14 | 只重新构建并重启（不动 nginx/unit） |
| **15** | **完全卸载**（删服务/站点配置/宝塔扩展目录/logrotate/续期钩子与 cron，配置副本存 `/root/cboard-uninstall-<时间戳>/`，最后残留扫描） |
| **16** | **自检并自动修复** |

## 十、面板重写 vhost 之后怎么办

宝塔面板里 **"保存站点设置" / "申请或续签 SSL"** 会**重写站点配置**，把脚本注入的片段冲掉
（表现为附件 404、SPA 白屏、HTTPS 失效）。处理方式：

```bash
bash bt-deploy.sh      # 菜单 16：自检并自动修复
```

实测效果：面板重写配置后（我们的标记全部消失、HTTPS 失效），只跑一次菜单 16 →
注入块与 443 配置全部补回、`nginx -t` 通过、HTTPS 恢复 200，且**面板自己的标记完整保留**。

## 十一、常见坑（实测）

| 坑 | 说明 / 对策 |
|----|-------------|
| 宝塔安装脚本空转 | 必须 `yes | bash install_lts.sh`（否则 stdin=EOF 时 99% CPU 忙循环） |
| nginx "装很久" | 宝塔是源码编译 OpenSSL+nginx，2 核 25–40 分钟属正常；用 `ps -ef | grep make` 确认在编译 |
| 目录名 ≠ 域名 | 脚本用**项目目录名**当域名 → 目录必须叫 `/www/wwwroot/<你的域名>`（或用 `DOMAIN=` 覆盖） |
| 面板占位文件 | 面板会生成 `index.html`/`404.html`/`.user.ini`；脚本会把 `root` 指到 `frontend/dist`，所以不影响，但清掉更干净 |
| HTTPS 403 / ACME 校验失败 | 宝塔 nginx 以 `www` 运行，产物权限不对会 403；脚本已自动修正（`fix_site_permissions`），菜单 16 也可修 |
| 面板里点续签失败 | 多为两种情况：① 证书由脚本（certbot）管 → 面板没有订单，请用菜单 10；② 面板页面上的**站点 id 已失效**（例如站点被删除重建过）→ 面板会报"网站丢失，无法继续申请证书"，重新打开面板 SSL 页面再操作即可 |
| 上传大文件 413 | 脚本已写入 `client_max_body_size 16m`；要更大就改配置或调 `.env` 的 `MAX_FILE_SIZE` |
| 忘了管理员密码 | 菜单 2 重置（当场实测登录）；或在 `.env` 设 `ADMIN_PASSWORD` 后菜单 8 重启 |
| 想彻底重来 | 菜单 15 完全卸载 → 重新建站 → 菜单 1 |
