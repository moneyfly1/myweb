# 客户端版本过滤与协议过滤

## 概述

系统提供两套**互斥**的订阅协议过滤机制，用于控制不同客户端收到的节点协议，避免客户端拿到不支持的节点导致订阅异常或节点过少。配置入口：**系统设置 → 协议过滤**。

---

## 一、两套机制的互斥关系

| 开关状态 | 生效机制 | 行为 |
|---------|---------|------|
| **客户端版本过滤【开启】** | 客户端能力过滤 | 按客户端**类型 + 版本**自动过滤其不支持的新协议；**忽略**下方协议白名单 |
| **客户端版本过滤【关闭】** | 协议白名单 | 按下方勾选的 `clash_protocols` / `universal_protocols` 白名单过滤 |

> **关键**：两套机制**不会同时生效**。开启客户端过滤时，DB 协议白名单被忽略——避免白名单误删客户端实际支持的协议（如白名单未勾选 vless，但客户端支持，若同时生效会被误删）。

`exclude` 参数（用户订阅 URL 中手动指定排除的协议）在两种模式下都生效。

---

## 二、客户端版本过滤（默认开启）

系统从请求的 **User-Agent** 识别客户端类型与版本，按内置能力表过滤：

| 客户端 | 识别特征 | 行为 |
|--------|---------|------|
| **老版 Clash**（非 Meta） | `ClashforWindows/0.x`、`ClashforAndroid`、`ClashX` | 过滤 VLESS/Reality/Hysteria2/TUIC/AnyTLS/WireGuard，只推 SS/VMess/Trojan |
| **Clash Meta** | `ClashMetaForAndroid/2.x`、`clash.meta/` | 全部支持，不过滤 |
| **Shadowrocket** | 构建号 `Shadowrocket/17xx` | <1744 过滤 Reality，<1600 过滤 Hy2/TUIC，<1800 过滤 AnyTLS |
| **sing-box / Stash** | `sing-box/1.x`、`Stash/` | 全部支持，不过滤 |
| **Surge / Loon / QuantumultX** | 版本号 | <5.0 过滤 Reality/Hy2/TUIC |
| **v2rayN/NG** | `v2rayN/` | 按版本过滤 |
| **无法识别**（curl/浏览器/未知） | — | 全量返回，保持现状 |

**适用场景**：老版 Clash（如 Clash for Windows 0.19.x）不支持 VLESS/Reality 等新协议，若推送会导致订阅解析失败。开启后自动只推送其支持的协议。

---

## 三、协议白名单（客户端过滤关闭时生效）

| 配置 | 作用范围 |
|------|---------|
| **Clash / Clash Meta**（`clash_protocols`） | Clash YAML / Surge / Sing-box / QuantumultX / Loon 订阅 |
| **通用 Base64**（`universal_protocols`） | Shadowrocket / v2rayN 等 base64 链接 |

勾选哪些协议，对应环境就只推送哪些。默认全选。

**适用场景**：需要**精细化控制**时——如只想给 Clash 用户推送 SS/VMess 两种协议，关闭客户端过滤后勾选即可。

---

## 四、配置步骤

1. 登录管理员后台 → **系统设置** → **协议过滤**。
2. 顶部「客户端版本过滤」开关：
   - **开启**（推荐默认）：自动按客户端能力过滤，无需手动维护。
   - **关闭**：手动勾选下方协议白名单。
3. 点击「保存协议过滤规则」。

> 💡 保存后**立即生效**（Redis 订阅缓存会自动失效），无需重启服务。

---

## 五、验证方式

用不同 UA 请求同一订阅，对比节点差异：

```bash
# 老版 Clash（客户端过滤开启时只拿 SS/VMess）
curl -A "ClashforWindows/0.19.23" "https://你的域名/api/v1/client/subscribe?token=订阅token&type=clash"

# Clash Meta（始终全量）
curl -A "ClashMetaForAndroid/2.11.24.Meta" "https://你的域名/api/v1/client/subscribe?token=订阅token&type=clash"
```

## 六、常见问题

| 问题 | 解决 |
|------|------|
| 老客户端订阅解析失败 | 确认「客户端版本过滤」已开启（默认）；或手动用 `exclude` 参数排除不支持的协议 |
| 某客户端节点太少 | 客户端过滤开启时按能力推送属正常；关闭后可用白名单精确控制 |
| 改了白名单不生效 | 确认「客户端版本过滤」已**关闭**（开启时白名单被忽略） |
| 如何排查 | 打开 `?type=clash` 手动请求订阅，查看返回的节点协议与 UA 是否匹配 |
